# Wedding Invitation

GitHub Pages에서 바로 배포할 수 있는 정적 모바일 청첩장입니다.

## 파일 수정

대부분의 개인정보/문구/날짜는 `js/data.js` 한 파일에서 수정할 수 있습니다.

- 신랑/신부 이름 및 영문명
- 혼주 성함 및 관계
- 예식 날짜/시간/장소
- 초대글 및 마지막 감사문구
- 히어로/갤러리 이미지 경로

## 혼주에게 연락하기

FAMILY 아래의 링크를 누르면 양가 혼주 연락처가 하단 모달로 열립니다. 전화·문자 링크는 기기의 전화/문자 앱으로 연결됩니다.

`js/data.js`의 `contacts.groom`(신랑 측), `contacts.bride`(신부 측)에 `father`(아버지), `mother`(어머니) 전화번호를 문자열로 입력합니다. 하이픈과 공백을 포함해도 됩니다. 성함은 `couple`의 혼주 성함을 함께 사용합니다.

번호가 비어 있거나 형식이 잘못된 항목은 전화·문자 버튼이 비활성화됩니다. 모달은 닫기 버튼, 바깥 배경, Esc 키로 닫을 수 있습니다.

브라우저가 기본 `dialog` API를 지원하지 않거나 실행에 실패하면 배경과 포커스 제어를 갖춘 대체 모달을 사용합니다.

## 마음 전하는 곳

‘마음 전하는 곳’ 전체(축의금 안내, 계좌정보, 답례품 안내·링크)는 기본으로 숨깁니다. 접속 주소에 `?mode=show`가 있을 때만 방명록 다음에 표시합니다.

- 기본 안내 숨김: `https://klee1123.github.io/1003/`
- 안내 표시: `https://klee1123.github.io/1003/?mode=show`
- 다른 파라미터와 함께 사용: `https://klee1123.github.io/1003/?v=20260915&mode=show`

`mode`가 없거나 `show` 이외의 값이면 숨깁니다. 기존 `?mode=simple` 주소에서도 숨겨집니다. `gift` 파라미터는 사용하지 않습니다.

`js/data.js`의 `accounts.groom`(신랑 측), `accounts.bride`(신부 측)에 계좌정보를 입력합니다.

- `label`: 관계 (신랑, 신부, 아버지, 어머니 등)
- `bank`: 은행명
- `number`: 계좌번호 (앞자리 0이 사라지지 않도록 문자열로 입력)
- `holder`: 예금주

은행명, 계좌번호, 예금주가 모두 입력된 계좌만 표시됩니다. 해당 측에 입력된 계좌가 없으면 ‘계좌정보를 준비 중입니다.’가 표시됩니다. 필요 없는 항목은 삭제해도 됩니다.

각 측을 누르면 계좌 목록이 펼쳐지며, ‘복사’ 버튼은 계좌번호만 복사합니다. 복사가 제한된 브라우저에서는 번호를 길게 눌러 직접 복사할 수 있습니다.

## 방명록

이름과 축하 메시지를 Google Sheets에 저장하는 방명록을 추가했습니다. 기존 GitHub Pages 구조를 유지하며 별도 서버나 DB 설치가 필요하지 않습니다.

**최초 연결이 필요합니다:** [방명록 설정 안내](apps-script/README.md)에 따라 전용 Google 시트와 Apps Script 웹 앱을 만든 뒤, `js/data.js`의 `guestbook.endpoint`에 웹 앱 `/exec` URL을 입력하세요. 연결 전에는 ‘방명록을 준비 중입니다.’ 안내를 표시합니다.

- 이름 최대 20자, 메시지 최대 300자, 수정·삭제 비밀번호 4~32자
- 최신 글부터 5개씩 표시, 더 보기·새로고침
- 글에 설정한 비밀번호로 수정·삭제, 삭제 전 확인 화면
- 저장 결과와 최신 목록을 함께 받아 등록·수정·삭제를 보통 2회 요청으로 처리
- 시트의 `상태` 열에서 공개·승인 대기·숨김 관리
- `guestbook.enabled: false`로 방명록 숨기기
- 방명록은 ‘마음 전하는 곳’ 앞에 배치하며 `mode` 값과 관계없이 표시

Google 배포용 코드는 [apps-script/Code.gs](apps-script/Code.gs)에 있습니다. 설정·실제 연결 확인·관리 방법은 [상세 안내](apps-script/README.md)를 참고하세요.

Apps Script 코드와 청첩장 파일은 같은 작업본으로 함께 배포합니다.

## 사진 교체

현재 사진은 레이아웃 확인용 SVG 플레이스홀더입니다.

1. `assets/images/hero.svg` 대신 실제 대표사진을 `hero.jpg` 등으로 넣습니다.
2. `assets/images/gallery/` 안에 갤러리 사진을 넣습니다.
3. `js/data.js`의 이미지 경로를 실제 파일명으로 변경합니다.

권장 규격:
- Hero: 세로 사진, 1600px 이상
- Gallery: 긴 변 1600~2400px 정도의 JPG/WebP

모바일의 메인 이미지 영역은 처음 표시된 높이를 유지합니다. 스크롤 중 내부 브라우저의 도구 모음이 접혀도 사진 배율이 바뀌지 않으며, 화면 회전 등으로 화면 너비가 바뀔 때 높이를 다시 계산합니다.

## GitHub Pages 배포

1. GitHub에서 새 repository를 만듭니다.
2. 이 폴더 안의 파일을 repository root에 업로드합니다.
3. `Settings > Pages`로 이동합니다.
4. `Deploy from a branch` 선택 후 `main` / `(root)`를 지정합니다.
5. 저장하면 `https://사용자명.github.io/저장소명/` 주소로 배포됩니다.

별도의 빌드 과정이나 서버가 필요하지 않습니다.

CSS·JS를 수정해 배포할 때는 `index.html`의 로컬 CSS·JS 주소에 붙은 `?v=` 값도 함께 변경합니다. 카카오톡 등 내부 브라우저에 이전 파일이 캐시되어 새 HTML과 섞이는 것을 방지합니다.
