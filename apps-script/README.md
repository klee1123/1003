# Google Sheets 방명록 연결

청첩장의 이름·축하글을 Google Sheets에 저장합니다. 작성자가 정한 비밀번호로 글을 수정·삭제할 수 있습니다. 사이트는 기존 GitHub Pages에서 그대로 운영하며, 서버나 DB를 따로 설치하지 않습니다.

## 1. 전용 시트 만들기

1. [새 Google 스프레드시트](https://sheets.google.com/create)를 만들고 `우빈 경진 방명록`처럼 이름을 붙입니다.
2. **확장 프로그램 → Apps Script**를 엽니다.
3. 기본 `Code.gs` 내용을 지우고, 이 폴더의 [Code.gs](./Code.gs) 전체를 붙여 넣어 저장합니다.
4. 상단 함수 선택에서 **setup**을 선택하고 **실행**합니다. 본인 계정으로 시트 접근 권한을 허용합니다.
5. 원래 스프레드시트에 **방명록** 탭이 생겼는지 확인합니다.

`setup`은 연결할 시트 ID를 스크립트 속성에 저장합니다. 다시 실행해도 기존 글을 지우지 않습니다. 기존 답례품 주소 수집 시트와 분리된 전용 시트를 사용하세요. 시트 공유 설정은 **제한됨**으로 유지해도 됩니다.

## 2. 웹 앱 배포

1. Apps Script 오른쪽 위 **배포 → 새 배포**를 선택합니다.
2. 배포 유형에서 **웹 앱**을 선택합니다.
3. **다음 사용자 인증 정보로 실행: 나**를 선택합니다.
4. **액세스 권한이 있는 사용자: 모든 사용자(Anyone)**를 선택합니다. 로그인한 Google 사용자만 허용하는 옵션과 다릅니다.
5. 배포하고 **웹 앱 URL**을 복사합니다. 주소는 `https://script.google.com/macros/s/.../exec` 형태입니다.

회사·학교 계정은 관리자가 익명 웹 앱을 제한할 수 있습니다. 모든 사용자 옵션이 없다면 해당 배포로는 로그인 없는 방명록을 운영할 수 없습니다.

## 3. 청첩장에 URL 입력

[../js/data.js](../js/data.js)의 `guestbook.endpoint`에 복사한 URL을 넣습니다.

```js
guestbook: {
  enabled: true,
  endpoint: "https://script.google.com/macros/s/여기에_배포_ID/exec"
},
```

실제 `/exec` URL을 그대로 넣으세요. 편집기 주소, 시트 주소, 테스트용 `/dev` 주소는 사용할 수 없습니다. URL은 공개되어도 되는 방명록 접속 주소이며 비밀번호나 API 키가 아닙니다.

`index.html`의 `js/data.js?v=...` 버전 문자열을 변경하고 평소처럼 GitHub Pages에 배포합니다. 주소가 비어 있거나 형식이 잘못되면 작성 폼 대신 **방명록을 준비 중입니다.**를 표시합니다. `enabled: false`이면 방명록 전체가 숨겨집니다. 방명록은 `mode` 값과 관계없이 표시됩니다. 그다음에 오는 ‘마음 전하는 곳’만 `?mode=show`일 때 표시됩니다.

## 4. 실제 연결 확인

1. Google 로그아웃 상태 또는 시크릿 창에서 `/exec?action=list`를 엽니다. 글이 없다면 `{"ok":true,"entries":[],"total":0,"nextCursor":""}` 형태의 JSON이 나와야 합니다.
2. 청첩장을 열고 이름·테스트 축하글·비밀번호를 입력해 글을 남깁니다.
3. 등록 완료 안내가 나오고 시트에 한 행이 추가되는지 확인합니다.
4. 다른 기기나 시크릿 창에서도 같은 글이 보이는지 확인합니다.
5. 글의 **수정**을 누르고 내용을 바꾼 뒤 작성할 때 정한 비밀번호로 저장합니다. 다른 창에서도 수정 내용이 보이는지 확인합니다.
6. **삭제**를 누르면 확인 폼이 열립니다. 틀린 비밀번호로는 삭제되지 않고, 올바른 비밀번호로는 글이 사라지는지 확인합니다.

실제 Google 배포 URL이 있어야 익명 접근, 리다이렉트와 브라우저 간 저장을 최종 확인할 수 있습니다. 로컬 자동 검증은 Google 서비스를 대체한 테스트 환경에서 실행하며 실제 계정 접근·배포 설정까지 검증하지 않습니다.

## 글 관리

| 열 | 용도 |
| --- | --- |
| 글 ID | 중복 등록 방지용 값. 수정하지 않습니다. |
| 작성 시각 (UTC) | 서버가 기록한 시각. 청첩장에는 한국 날짜로 표시합니다. |
| 이름 | 방문자가 입력한 이름 |
| 축하 메시지 | 방문자가 입력한 글 |
| 상태 | `published`: 공개 / `pending`: 승인 대기 / `hidden`: 숨김 / `deleted`: 작성자가 삭제 |
| 기기 ID | 동일 브라우저의 연속 등록 제한용 임의 값. 공개 목록에는 포함하지 않습니다. |
| 비밀번호 검증값 | 원문이 아닌 서버의 검증용 값. 수정하지 않습니다. |
| 비밀번호 오류 횟수 / 잠금 만료 | 글별 비밀번호 오류 제한에 사용합니다. |
| 최근 요청 ID / 최근 작업 / 최근 요청 검증값 | 재시도·동시 수정 처리용 값. 수정하지 않습니다. |

- **숨김:** 상태를 `hidden`으로 바꿉니다. 시트에서 행 숨기기 기능을 사용하는 것과 다릅니다.
- **다시 공개 / 승인:** 상태를 `published`로 바꿉니다.
- **삭제:** 필요한 행을 시트에서 삭제합니다. 중복 요청 확인 이력도 지워지므로 일반적인 관리는 `hidden`을 권장합니다.
- **처음부터 승인 후 공개:** `Code.gs` 상단의 `REQUIRE_APPROVAL`을 `true`로 바꾸고 웹 앱의 새 버전을 배포합니다. 글 작성자는 접수 완료 안내를 보고, 관리자가 `published`로 바꾸기 전까지 목록에는 나타나지 않습니다.
- **작성자의 수정:** 글 아래의 **수정**을 누르고 이름·내용을 바꾼 뒤 기존 비밀번호로 저장합니다. 승인 모드이면 수정한 글도 다시 `pending`이 됩니다. 관리자가 숨긴 글은 작성자가 수정해도 공개되지 않습니다.
- **작성자의 삭제:** **삭제**를 누른 뒤 확인 폼에서 비밀번호를 입력하고 **삭제하기**를 누릅니다. 이름·메시지는 시트에서 비우며, 재시도를 확인하기 위한 최소 기록과 검증값은 `deleted` 상태로 남깁니다. 관리자는 이 행을 별도로 삭제할 수 있습니다.
- **비밀번호 분실:** 원문 복구·비밀번호 재설정 기능은 없습니다. 관리자에게 시트에서 글을 변경하거나 삭제해 달라고 요청해야 합니다.
- **방명록 종료:** `js/data.js`의 `enabled`를 `false`로 변경하고 사이트에 반영합니다. 기존 웹 앱 URL로도 더 이상 글을 받지 않으려면 Apps Script의 **배포 관리**에서 해당 배포를 보관 처리합니다.

첫 행의 열 이름과 순서를 유지해 주세요. 정렬은 행 전체에 적용하세요. 상태나 글 내용의 시트 수정은 다음 조회부터 반영되며, 이미 열려 있는 청첩장에서는 **새로고침**을 누르면 됩니다.

## 동작과 제한

- 최신 글부터 5개씩 표시하며 **축하글 더 보기**로 이어서 읽습니다.
- 이름 최대 20자, 메시지 최대 300자를 브라우저와 서버에서 검사합니다. 비밀번호는 화면에서 4~32자로 입력받으며 원문 대신 파생된 검증 요청 값을 서버로 보냅니다. 일부 이모지는 글자 수를 2 이상 사용합니다.
- 새 글은 기본적으로 바로 공개합니다. 입력한 이름과 메시지만 목록에 공개하며 비밀번호 관련 값은 공개 응답에서 제외합니다.
- 같은 기기는 30초 간격으로 작성할 수 있습니다. 기기 ID를 바꾸거나 브라우저 저장소를 지우면 우회할 수 있는 간단한 제한이며, 본인 인증이나 강력한 스팸 차단 수단은 아닙니다.
- 숨겨진 스팸 입력란, 동시 저장 잠금, 동일 요청 ID 재사용으로 일반적인 자동 입력·중복 클릭·재시도를 처리합니다.
- 방문자 입력은 시트에 RichTextValue로 저장하고 화면에는 `textContent`로 표시하여 수식이나 HTML로 실행하지 않습니다.
- 글은 Google Sheets에 저장됩니다. `localStorage`에는 연속 등록 제한에 사용하는 임의 기기 ID만 저장합니다. 저장소 사용이 차단되어도 작성할 수 있습니다.
- 비밀번호는 브라우저의 Web Crypto로 PBKDF2-HMAC-SHA-256, 600,000회, 글마다 다른 salt(글 ID)를 사용해 처리합니다. 서버는 이 값에 별도 비밀키로 HMAC-SHA-256을 적용해 저장합니다. 원문 비밀번호와 전송용 파생값을 시트·브라우저 저장소·조회 URL에 저장하지 않습니다. HTTPS와 Web Crypto를 지원하는 브라우저가 필요합니다.
- 서버 비밀키는 Apps Script의 `GUESTBOOK_PASSWORD_KEY` 속성에 한 번 생성합니다. 이 값은 공개 코드·시트·응답에 포함하지 않습니다. 키를 삭제하거나 변경하면 기존 비밀번호를 확인할 수 없으므로 유지하세요. 기존 보호 글이 있는데 키가 사라진 경우 `setup`은 임의의 새 키로 덮어쓰지 않습니다.
- 비밀번호 오류가 5회 누적되면 해당 글의 수정·삭제를 15분 제한합니다. 제한은 시트에 저장하므로 브라우저를 바꾸어도 적용됩니다. 성공한 변경은 오류 횟수를 초기화합니다.
- Google Apps Script에는 계정별 실행·동시 요청 할당량이 있습니다. 방명록은 페이지 진입 시 한 번 미리 조회합니다. 첫 조회의 시간 초과·네트워크 오류는 한 번 자동 재시도하며, 주기적으로 조회하지 않습니다. 목록 요청은 전체 방명록을 읽으므로 소규모 청첩장용 구조입니다.

### 통신 방식

GitHub Pages와 Apps Script는 서로 다른 출처입니다. 공개 목록·요청 접수 상태는 **읽기 전용 JSONP**, 새 글·수정·삭제는 폼 인코딩 **POST**로 처리합니다. JSONP 콜백 이름은 서버에서 엄격하게 제한합니다. 비공개 글 내용·기기 ID·시트 ID·비밀번호 검증값은 공개 응답에 포함하지 않습니다.

`no-cors` POST 응답만으로 성공을 판단하지 않습니다. 고유한 요청 ID를 서버에서 다시 조회해 실제 저장이 확인된 경우에만 등록 완료를 표시합니다. 확인에 실패하면 입력을 유지하며, 같은 페이지에서 같은 내용으로 다시 누르면 같은 ID를 사용합니다. 페이지를 새로 열면 이 재시도 ID는 유지되지 않습니다.

수정·삭제는 화면에서 읽은 글의 버전도 함께 확인합니다. 다른 요청으로 글이 바뀌었으면 오래된 요청은 거절하여 최신 내용을 덮어쓰지 않습니다. 비밀번호와 버전 확인 및 저장은 같은 잠금 안에서 처리하며, 변경 내용과 접수 결과를 한 행에 함께 기록합니다.

### 통신 속도

- 첫 목록은 페이지 진입 시 미리 불러오고 최대 30초 기다립니다. 시간 초과·네트워크 오류가 나면 0.75초 후 한 번 자동 재시도하며, 재시도는 최대 15초 기다립니다. 두 요청 모두 실패하면 새로고침 안내를 표시합니다. 서버가 반환한 오류나 잘못된 응답 형식은 즉시 안내합니다.
- 목록을 한 번 불러온 뒤의 조회와 저장 결과 확인은 요청마다 최대 15초 기다립니다. 저장 후 최신 목록을 받은 경우에는 진행 중인 초기 조회·재시도가 그 목록을 덮어쓰지 않습니다.
- 저장·수정·삭제는 **POST → 결과·목록 확인**의 2회 요청으로 처리합니다. 결과 확인을 재시도하는 경우에는 요청이 늘어날 수 있습니다.
- `action=status`의 성공 응답에는 항상 최신 공개 목록(`list`)이 포함됩니다. 서버에서도 같은 시트 읽기 결과를 재사용합니다.
- 최초 목록 조회가 끝나기 전에도 글을 작성할 수 있습니다.
- 먼저 보낸 목록 응답이 늦게 도착해도 저장 후 목록을 덮어쓰지 않습니다. 같은 화면에서 작업이 겹쳐 결과가 역순으로 도착하면 목록을 새로 조회합니다.
- 저장은 확인됐지만 목록 응답 형식에 문제가 있으면 저장 완료 상태를 유지하고 목록 영역에 새로고침 안내를 표시합니다.
- Apps Script의 `Code.gs`와 청첩장의 `index.html`·`js/guestbook.js`는 같은 작업본으로 함께 배포합니다.

Apps Script 실행과 Google Sheets 접근 시간은 여전히 발생합니다. 통신 완료 전에는 성공으로 표시하지 않으며, 비밀번호 처리 강도와 5회 오류·15분 잠금 기준을 유지합니다.

## 문제가 생기면

- **준비 중 안내만 표시됨:** `endpoint`가 실제 `/exec` 주소인지 확인합니다. 수정한 `data.js`가 캐시에 남았다면 HTML의 `?v=` 값도 변경합니다.
- **로그인 또는 권한 요청 화면:** 실행 주체가 **나**, 액세스가 **모든 사용자**인지 확인합니다.
- **연결 오류:** `setup`을 실행했는지, 방명록 탭과 첫 행의 이름·순서를 바꾸지 않았는지 확인합니다. Apps Script의 **실행** 메뉴에서 서버 오류를 확인할 수 있습니다.
- **코드를 수정했는데 바뀌지 않음:** **배포 → 배포 관리 → 수정 → 버전: 새 버전 → 배포**로 갱신합니다. 기존 배포를 갱신하면 URL을 유지할 수 있습니다.
- **등록 여부 확인 실패:** 시트에 글이 있는지 확인하고, 같은 페이지에서 입력을 바꾸지 않은 채 다시 눌러보세요. 할당량 초과나 일시적 네트워크 오류일 수 있습니다.

```sh
node --test tests/guestbook*.test.cjs
```
